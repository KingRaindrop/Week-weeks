## 验收分层

编译通过和纯逻辑测试不代表 Android 通知送达，也不代表交互和视觉验收完成。尤其 API 32 的 MuMu 不能代替 Android 16 / API 36。

### Android 16 / API 36 提醒验收（待实际设备）

记录手机型号、系统版本/API、应用版本、前后台、屏幕状态、勿扰、电池策略以及通知/精确闹钟权限。

1. 设置 → 提醒状态，确认权限、应用总开关、原有通知渠道重要性/声音/振动、精确提醒能力。
2. 立即发送测试通知：分别记录通知栏、声音、振动、横幅、锁屏展示。不要仅记录“有效/无效”。
3. 短延时测试提醒：按界面预计时间等待，分别覆盖前台、后台、息屏；非精确情况下记录实际延迟。
4. 拒绝通知权限、关闭应用通知、关闭渠道、静音渠道；每项核对诊断原因和设置入口。
5. 允许/拒绝精确闹钟权限；拒绝时必须明确提示可能延迟，不得以“已调度”声称准时送达。
6. 使用未来的真实课程和个人日程提醒各一项，检查调度 → 接收 → 通知提交记录。
7. 修改或删除真实课程/日程后，旧 generation 的广播必须被过滤；测试提醒不修改生产提醒计划。
8. 系统重启/应用更新后的恢复行为单独检查；不通过创建新渠道、全屏强制拉起页面绕过系统设置。

### 主弹层交互验收（待设备）

课程与个人日程均覆盖：

- 长按后立刻点按、连续长按、交替点击两个块。
- 编辑器显示时直接调用底层详情入口，不得创建新主窗口。
- 关闭动画中点击；详情转编辑后快速返回。
- 详情转编辑必须先关闭旧详情；旧关闭回调不能释放新编辑器令牌。
- 返回键先处理键盘，再触发草稿确认；取消放弃后编辑器仍显示。
- 删除/放弃确认可覆盖编辑器，但不能叠出多个主编辑器。
- 页面重建/主题切换后恢复已有草稿和已有受支持的详情状态；已关闭草稿不可复活。

### 数字周选择验收（待设备）

- 顶部周标题打开第 1～N 周，N 跟随校历配置。
- 正在查看周与现实本周分别标记；点选同步日期、周标题、课程、个人日程。
- “回到本周”在学期内外均可用；“按日期查找”保留学期外日程能力。
- 面板自动定位到正在查看周附近，窄屏、大字体减少列数，所有操作可滚动访问。
- 简体、繁体、英语 × 深浅色 × 280/360/600dp × 1/1.5/2 倍字体。

## 第二轮（2026-11-13）：导入链路与设置窗口纳管

### 行为

- 导入预览、节次数不足提示、导入结果（含跳过原因）、导入后首次校历设置依次交接：每一步在上一窗口真正关闭后才打开，中间不留可插入的输入间隙。
- 文本导入：识别成功后先关闭粘贴面板，再打开预览，不再叠在粘贴面板上。
- 后台 PDF 结果或提醒弹窗到达时若已有窗口（含设置浮层），不再覆盖，而是保留最新一条，待窗口全部关闭且页面在前台时再显示。等待中的 PDF 结果在页面重建后重新解析。
- 节次设置、学期校历、字体、语言、主题色、随机配色、删除配置、提醒关闭提示、经典课程编辑器均纳入同一主窗口所有权；连续点击不会叠出第二个窗口。
- 节次规则编辑、校历日期选择、经典编辑器的删除确认/临时周数仍属所在窗口的从属窗口；节次规则编辑一次只允许一个，父窗口关闭时一并关闭。

### 渐进拆分

- [`ImportPlanner.java`](<../app/src/main/java/com/weekweeks/app/ImportPlanner.java>)：导入合并规则（同名同时段同周次原地更新教室/老师、完全相同跳过、上限跳过）从 MainActivity 移出，纯 Java，可单测。课程数据结构、存储、解析和配色规则未改。
- [`OwnedDialog.java`](<../app/src/main/java/com/weekweeks/app/OwnedDialog.java>)：普通对话框与所有权令牌的绑定（显示失败释放、清理后释放、关闭后交接）。
- [`ModalCoordinator.java`](<../app/src/main/java/com/weekweeks/app/ModalCoordinator.java>)：新增空闲回调，只在真正无人持有时触发，交接和销毁后不触发。
- [MainActivity.java](<../app/src/main/java/com/weekweeks/app/MainActivity.java>) 仍约 6,600 行；本轮只移出导入合并与对话框绑定，未拆课程编辑或提醒计划生成。
